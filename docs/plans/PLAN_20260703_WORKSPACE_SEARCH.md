# PLAN_20260703 — 워크스페이스 내 페이지 검색

> 작성일: 2026-07-03 · 상태: 설계(구현 전) · 브랜치: main

## 배경 / 목적

한 워크스페이스 안에서 사용자가 **이전에 작성해 둔 기록을 다시 찾고 싶은** 경우가 있다. 현재는 사이드바 페이지 목록을 눈으로 훑는 방법뿐이라, 페이지가 많아지면(예: 날짜별 업무일지 30~40개) 원하는 내용을 찾기 어렵다.

목표: 활성 워크스페이스 내 페이지를 **제목과 본문 내용으로 검색**하고, 결과에서 바로 해당 페이지로 이동한다.

## 핵심 결정 요약

| 항목 | 결정 |
|---|---|
| 검색 UI | 사이드바 **Pages 헤더 우측(개수 배지 옆)**의 `⌕` 아이콘 버튼 → 클릭 시 **모달** |
| 아이콘 | 유니코드 글리프 `⌕`(U+2315). 이모지/이미지 아님 — `↻`·`⚙`처럼 단색 글리프로 앱 스타일 통일 |
| 검색 범위 | 페이지 **제목 + 본문**(ProseMirror JSON에서 평문 추출) |
| 결과 표시 | 페이지 제목 + 매칭된 본문 주변 **스니펫 미리보기**(검색어 하이라이트) |
| 검색 위치 | **클라이언트 사이드**(이미 로드된 `pages` 상태 대상) |
| 매칭 방식 | 대소문자 무시 **부분 문자열**(substring) |
| 결과 선택 | 클릭/↑↓+Enter → 해당 페이지로 이동 후 모달 닫힘. **접힌 조상은 자동 펼침**(사이드바에서 위치 보이게) |
| 매칭 하이라이트(에디터 내) | **v1 제외**(페이지 열기까지만). 후속 과제로 분리 |
| 검색 대상 범위 | **활성 워크스페이스 1개**(전체 워크스페이스 교차 검색 아님) |

## 아키텍처 — 클라이언트 사이드 검색

앱은 이미 활성 워크스페이스의 **모든 페이지를 `content`(ProseMirror JSON)까지 포함해 `pages` 상태에 로드**한다(`GET /api/pages?workspaceId=` 의 select에 content 포함, `notion-lite-app.tsx`의 `loadPages`). 따라서 검색 대상 데이터가 이미 메모리에 있으므로:

- 새 API 엔드포인트, DB 마이그레이션, Postgres FTS **불필요**.
- 입력 즉시 클라이언트에서 필터링 → 수십 개 규모에선 체감 지연 없음.

**확장 포인트(YAGNI, 지금은 미구현)**: 페이지가 수백~수천 개로 커지거나, 로드되지 않은 페이지까지 검색해야 하면 서버 사이드 검색(예: Postgres `to_tsvector` FTS + 전용 API)으로 이관한다. 현재 규모에선 과설계이므로 클라이언트 사이드로 시작한다.

## 컴포넌트 구성

### 1. 텍스트 추출 유틸 (`lib/`)

- ProseMirror `content` JSON에서 검색용 **평문**을 추출하는 함수.
- 재사용 검토: 기존 `lib/tiptap-to-markdown.ts`가 있으나 마크다운 기호가 섞이므로, 검색 정확도를 위해 **text-only 추출기**를 별도로 두는 편이 깔끔하다(노드 트리를 순회하며 `text` 노드만 이어붙이고 블록 경계에 공백/개행 삽입).
- 순수 함수로 단위 테스트 가능.

### 2. `SearchModal` 컴포넌트 (신규, `components/search-modal.tsx`)

- 순수 표현 컴포넌트. props:
  - `pages: PageRecord[]` — 검색 대상(활성 워크스페이스 페이지)
  - `open: boolean`, `onClose: () => void`
  - `onSelect: (pageId: string) => void`
- 내부: 검색 입력, 결과 리스트(제목 + 스니펫), 키보드 내비게이션(↑↓/Enter/Esc).
- 검색 로직(매칭·스니펫·정렬)은 이 컴포넌트 또는 얇은 훅(`useMemo`)으로 캡슐화. 부모의 상태와는 props로만 통신.

### 3. `notion-lite-app.tsx` 통합

- **아이콘 배치**: 사이드바 Pages 헤더 행(현재 `Pages` 라벨 + 개수 배지, `justify-between`)의 **우측 개수 배지 옆**에 `⌕` 아이콘 버튼 추가. 검색은 Pages 섹션 전체에 대한 동작이므로 섹션 헤더가 정석 위치이며, "새 페이지" 생성 입력줄과 역할이 분리돼 의미가 명확하다.
- **아이콘/스타일**: 유니코드 글리프 `⌕`(U+2315). 기존 버튼과 동일하게 `border border-black` + `bg-[#50504d]` + `shadow-[2px_2px_0_#000]`, hover 시 `bg-[#baf7c8]` + `text-black`. 크기는 헤더에 맞춰 기존 9×9(`h-9 w-9`)보다 작은 버튼으로 조정 가능.
- 클릭 시 `searchOpen` 상태 토글로 모달 오픈.
- `onSelect`는 기존 `selectActivePage(pageId)` 재사용. (선택 시 접힘 조상 자동 펼침은 후속 고려 — 아래 참고.)

## 검색 / 결과 동작

### 매칭

- 검색어를 소문자화하고, 각 페이지의 `title` + 추출 평문을 소문자화해 **부분 문자열 포함** 여부로 판정. 한글에 대해 가장 예측 가능한 동작.
- 빈 검색어면 결과 없음(최근 수정 페이지 목록 표시는 v1 범위 밖).

### 결과 행

- 페이지 **제목** + 매칭된 본문 주변 **스니펫**(매칭 지점 앞뒤 약 30자, 말줄임 `…`).
- 검색어에 해당하는 부분을 `<mark>`로 하이라이트.
- 제목에서 매칭된 경우 제목 하이라이트, 본문에서 매칭된 경우 스니펫 표시.

### 정렬

- 1순위: **제목 매칭** 페이지, 2순위: 본문 매칭 페이지.
- 각 그룹 내에서는 `updated_at` 최근순.

### 선택

- 클릭 또는 ↑↓ 이동 후 Enter → `onSelect(pageId)` → 페이지 이동 + 모달 닫힘.
- Esc → 모달 닫힘.

## v1 범위 밖 (후속 과제)

- **에디터 내 매칭 위치로 스크롤·하이라이트**: 페이지를 여는 것까지만 하고, 에디터 안에서 검색어 위치로 이동·강조하는 것은 에디터(ProseMirror) 내부 제어가 필요해 복잡도가 크므로 별도 과제로 분리.
- **전체 워크스페이스 교차 검색**, **서버 사이드 FTS**, **검색 히스토리/최근 검색어**.

## 테스트 전략

- **텍스트 추출 유틸**: 다양한 ProseMirror 문서(문단/제목/목록/표/코드블록/중첩)에서 기대 평문이 나오는지 단위 테스트.
- **검색 로직**: 제목만 매칭 / 본문만 매칭 / 둘 다 / 대소문자 / 정렬 순서 / 스니펫 경계 케이스.
- **통합(Playwright)**: 아이콘 클릭 → 모달 → 검색어 입력 → 결과 노출 → 선택 시 해당 페이지로 이동. 기존 세션 주입 방식 재사용.

## 확정 사항

- **v1 범위 = "페이지 열기까지만"**(2026-07-03 확정). 에디터 내 매칭 위치 스크롤·하이라이트는 후속 과제로 분리(위 "v1 범위 밖" 참고).

## 세부 수치(구현 중 조정 가능)

- 스니펫 길이(±30자)와 결과 최대 개수 등은 구현하며 미세 조정.
