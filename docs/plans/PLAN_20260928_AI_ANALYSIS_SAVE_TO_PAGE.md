# AI 분석 결과를 새 페이지로 저장하는 계획

**작성일:** 2026-09-28  
**상태:** 계획  
**관련 문서:** [워크스페이스 AI 분석 구현 계획](./PLAN_20260926_WORKSPACE_AI_ANALYSIS_IMPLEMENTATION.md)

## 1. 목표

사용자가 AI 분석 결과를 검토한 뒤, 필요한 경우 워크스페이스에 새 페이지로 저장한다. 저장은 명시적인 사용자 동작으로만 실행하며 기존 원본 페이지는 수정하지 않는다.

## 2. 사용자 흐름

1. 사용자가 페이지를 선택해 요약·정리·분석 등을 실행한다.
2. 결과 패널에서 결과를 검토하고 출처 링크로 원본을 확인한다.
3. `새 페이지로 저장`을 선택한다.
4. 저장 전에 페이지 제목과 생성 위치를 확인·수정한다.
5. 저장에 성공하면 새 페이지를 열고, 결과 패널로 돌아올 수 있는 안내를 제공한다.

결과를 단순히 닫거나 AI 분석을 다시 여는 동작은 페이지 생성이나 저장을 유발하지 않는다.

## 3. MVP 범위

### 포함

- 결과 패널에 명시적인 `새 페이지로 저장` 동작 제공
- 기본 제목 제안: 분석 결과 제목
- 생성 위치 선택:
  - 현재 workspace의 최상위
  - 사용자가 선택한 기존 페이지 아래 하위 페이지
- 저장 직전 제목과 위치 확인
- 결과를 Cowork26 Tiptap 문서 구조로 변환해 저장
- 결과의 overview, 섹션, 확인할 사항, 출처 페이지 링크 포함
- 성공·실패 상태와 중복 클릭 방지
- 성공 후 생성된 페이지로 이동

### 제외

- 원본 페이지 내용에 결과를 덧붙이거나 덮어쓰기
- 자동 저장, 분석 종료 시 자동 페이지 생성
- 분석 결과 전체의 server-side history 보관
- PDF/Markdown 다운로드와 외부 문서 연동
- 여러 결과를 한 페이지에 합치는 기능
- 이전 저장 결과를 같은 페이지에 자동 병합하는 기능

## 4. 페이지 본문 구성

저장되는 페이지는 편집 가능한 일반 Cowork26 페이지로 만든다. 초기 문서 구조는 다음과 같다.

```text
제목: {분석 결과 제목}

분석 개요
{overview}

{분석 섹션 제목}
- {항목}
  출처: S1 · S3

확인할 사항
- {항목}
  출처: S2

출처 페이지
- S1 · {원본 페이지 제목}
- S2 · {원본 페이지 제목}
```

- 출처 label은 저장 시점의 원본 page ID에 대응하는 내부 링크로 변환한다.
- 링크에는 일반 편집기에서 지원하는 안전한 page URL 형식만 사용한다.
- provider가 반환한 HTML이나 임의 Tiptap JSON을 그대로 저장하지 않는다.
- 검증된 structured output을 앱에서 Tiptap node로 생성한다.
- 결과 페이지는 분석에 포함된 원본 page 목록과 분석 mode를 확인할 수 있어야 한다.

## 5. UX 및 실패 처리

- 저장 전 간단한 확인 화면에서 제목과 생성 위치를 편집한다.
- 기본 생성 위치는 현재 workspace 최상위로 둔다. 원본 다중 선택 시 특정 원본 아래에 임의로 생성하지 않는다.
- 사용자가 위치를 직접 선택하면 해당 page의 자식으로 생성한다.
- 저장 중에는 버튼 중복 실행을 막고 진행 상태를 표시한다.
- 저장 성공 시 새 page를 열고 `AI 결과 페이지를 생성했습니다` 안내를 표시한다.
- 실패 시 입력한 제목·위치를 유지하고 재시도할 수 있게 한다.
- 응답이 유실되어 성공 여부가 불명확한 상황에서 중복 page 생성을 막도록 저장 요청에 idempotency key를 적용한다.
- 닫기, 뒤로가기, 취소는 저장을 실행하지 않는다.

## 6. 보안 및 데이터 경계

- 생성 요청은 fresh authentication을 사용한다.
- 서버는 workspace membership과 page 생성 권한(`owner` 또는 `editor`)을 재검사한다.
- workspace ID와 parent page ID의 소속이 일치하는지 서버와 기존 DB hierarchy trigger로 확인한다.
- 클라이언트가 보낸 arbitrary HTML/JSON을 신뢰하지 않는다. 결과를 제한된 명세로 보내거나, 서버가 허용된 필드만 검증해 문서 JSON으로 만든다.
- 제목과 본문 크기를 기존 페이지 생성 API 제한에 맞춘다. 결과 최대 길이가 더 크면 별도 상한을 정하고 UI에서 안내한다.
- source page가 삭제되었거나 접근 권한이 사라진 경우 저장은 안전한 텍스트 fallback을 사용하거나 저장을 막고 사용자가 취소·재분석하도록 한다. 내부 링크에 깨진 대상을 만들지 않는다.
- 분석 ledger에 결과 원문을 저장하지 않는 현재 원칙은 유지한다. 사용자가 새 페이지 저장을 선택한 경우에만 해당 결과가 일반 페이지 콘텐츠로 영구 저장된다.

## 7. 구현 후보

- 재사용 가능한 서버 page creation service 또는 기존 `POST /api/pages` 계약 검토
- 결과 저장용 request schema와 분석 결과 serialization helper 추가
- 결과 UI에 save confirmation form/dialog 연결
- idempotency 보장 방식은 현재 page create 경로의 동시성 및 unique 지원 여부를 확인한 뒤 결정
- 생성한 page ID를 기존 page navigation/reveal 흐름에 전달
- 결과 페이지의 생성자·생성 시각 metadata는 일반 page 필드가 제공하는 범위에서만 표시

## 8. 테스트 및 완료 기준

- owner/editor는 저장할 수 있고 viewer/비멤버는 거부된다.
- 다른 workspace의 parent page ID로 생성할 수 없다.
- arbitrary HTML, unknown citation label, 비정상 길이/형식은 거부된다.
- 저장 전 취소와 패널 닫기는 DB에 page를 만들지 않는다.
- 저장 후 page 제목, 콘텐츠 구조, 출처 링크, parent/workspace 관계가 검증된다.
- 반복 요청과 응답 재시도에서 동일 사용자 동작이 중복 page를 만들지 않는다.
- 원본 분석 대상 page의 제목·본문·revision은 변하지 않는다.
- 모바일과 데스크톱에서 확인 폼, 긴 결과 스크롤, 성공 후 탐색 흐름을 확인한다.

## 9. 결정이 필요한 세부사항

- 기본 생성 위치를 최상위로 고정할지, 마지막 선택 위치를 같은 세션에서만 기억할지
- 결과 본문에 분석 provider/model/완료 시각을 메타 정보로 포함할지
- 한 workspace에서 저장 가능한 분석 결과 page 수 또는 크기에 별도 제한을 둘지
- 원본 page가 삭제된 경우 저장을 막을지, 해당 출처를 텍스트로 보존할지

초기 구현은 별도 사용자 요구가 없으면 최상위 생성, provider/model/시각 표기, 일반 page 생성 권한과 기존 페이지 크기 제한 재사용을 기본안으로 한다. 출처 page가 사라졌다면 저장을 중단하고 최신 문서로 다시 분석하도록 안내한다.
