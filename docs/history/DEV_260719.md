# DEV_260719 — 페이지 간 복사 시 전체가 코드 블록으로 변환되는 문제

## 상태

- [x] 증상 및 원인 분석
- [x] 붙여넣기 우선순위 수정
- [x] 회귀 테스트 추가
- [x] 정적/자동 검증
- [ ] 실제 브라우저 페이지 간 복사 검증

## 증상

현재 페이지의 리치 본문을 복사해 다른 페이지에 붙여넣으면 다음 문제가 발생한다.

- 본문 전체가 하나의 코드 블록으로 들어간다.
- 코드 블록 언어 배지에 `ini`가 표시된다.
- 제목, 문단, 굵게, 링크 등 원본 서식과 블록 경계가 사라진다.
- 이미지나 Mermaid 같은 비텍스트 노드가 포함된 경우 누락될 수 있다.

대표 원문에는 아래처럼 `=`가 반복되는 일반 문서가 포함되어 있다.

```txt
M = "마스터"
MA = "영화"
CA = "기기변경"
```

## 원인

붙여넣기는 `components/document-editor.tsx`의 `handlePaste`에서 처리한다.

에디터 내부 복사 시 클립보드에는 다음 두 형식이 함께 들어간다.

- `text/html`: ProseMirror의 `data-pm-slice` 마커와 원본 리치 구조
- `text/plain`: 서식을 제거한 평문

수정 전 처리 순서는 소스 코드 휴리스틱이 `data-pm-slice` 가드보다 앞에 있었다.
`looksLikeSourceCode()`의 `CODE_LINE_SIGNAL`은 일반 문서의 반복된 `=` 줄도 코드 신호로 판정한다.
신호가 2줄 이상이고 전체 비율이 30% 이상이면 붙여넣기 전체를 `codeBlock` 하나로 재구성한다.

이 과정에서 `text/html`은 버려지고 `text/plain`만 코드 블록의 텍스트 노드로 사용된다.
따라서 리치 서식과 비텍스트 노드가 유실되며, `detectCodeLanguage()`의 자동 감지 결과로 `ini` 배지가 표시된다.

이 우선순위는 2026-07-08의 VS Code/KQL 붙여넣기 수정에서 내부에 평문으로 들어간 코드를 다시 복사했을 때 코드 블록으로 교정하기 위해 도입됐다. 그러나 페이지 내부 복사의 기본 의미인 원본 구조 보존과 충돌한다.

## 목표

- 페이지 내부 복사·붙여넣기는 원본 ProseMirror HTML 구조를 우선한다.
- 제목, 문단, 인라인 서식, 표 및 비텍스트 노드를 가능한 그대로 보존한다.
- 외부 코드 에디터 및 순수 `text/plain` 소스 코드 자동 감지는 유지한다.
- 외부 Markdown 붙여넣기 변환은 유지한다.

## 비목표

- 코드 감지 휴리스틱 전체를 재설계하지 않는다.
- 클립보드에 `text/plain`만 제공되는 외부 프로그램의 원본 서식 복원은 다루지 않는다.
- 붙여넣기 UI나 코드 블록 렌더링 스타일은 변경하지 않는다.

## 구현 계획

### 1. 내부 복사 우선순위 복원

`pasteHtml.includes('data-pm-slice')` 가드를 소스 코드 휴리스틱보다 앞으로 이동한다.

처리 원칙:

1. 코드 에디터 전용 메타 또는 monospace HTML은 기존 `getCodeEditorPaste()`로 처리한다.
2. Excel/Google Sheets HTML 표는 기존처럼 네이티브 표 붙여넣기에 위임한다.
3. `data-pm-slice`가 있는 내부 복사는 즉시 네이티브 ProseMirror 붙여넣기에 위임한다.
4. 내부 복사가 아닌 경우에만 일반 소스 코드 휴리스틱을 적용한다.
5. 나머지는 Markdown 재파서 또는 기본 붙여넣기로 처리한다.

내부에서 평문으로 저장된 코드/KQL을 재복사해 자동으로 코드 블록으로 교정하던 동작은 제거된다. 복사·붙여넣기의 데이터 충실도를 우선하며, 외부에서 새로 붙여넣는 코드/KQL 자동 감지는 유지한다.

### 2. 회귀 테스트

자동 회귀 테스트에서 `handlePaste`의 핵심 처리 순서를 고정한다.

```sh
npm run test:editor-paste-priority
```

브라우저 수동 검증에서는 `text/plain`과 `data-pm-slice`가 포함된 `text/html`이 함께 전달되는 실제 페이지 간 복사를 확인한다.

검증 항목:

- 반복된 `=`가 있는 내부 리치 문서가 코드 블록으로 변환되지 않는다.
- 문단 및 굵게 같은 HTML 구조가 유지된다.
- 외부 순수 코드/KQL 붙여넣기는 계속 코드 블록이 된다.
- 외부 Markdown 문서는 기존 파서로 렌더링된다.

### 3. 검증

```sh
npm run typecheck
```

가능한 경우 브라우저 테스트도 실행한다.

```sh
TEST_PASSWORD=... node scripts/editor-syntax-test.cjs
```

## 완료 기준

- 페이지 간 내부 복사에서 전체 코드 블록 오변환이 발생하지 않는다.
- `ini` 배지가 잘못 생성되지 않는다.
- 외부 코드 및 Markdown 붙여넣기 경로가 유지된다.
- TypeScript 타입 검사가 통과한다.
- 검증 결과와 남은 수동 확인 항목을 이 문서에 기록한다.

### 남은 수동 검증

현재 환경에는 `TEST_PASSWORD`가 설정되어 있지 않고 포트 3001의 개발 서버도 실행 중이지 않아 로그인 기반 브라우저 테스트는 실행하지 않았다.

배포 전 실제 앱에서 다음을 확인한다.

1. 문제가 발생한 원본 페이지 본문을 복사한다.
2. 다른 페이지에 붙여넣는다.
3. 전체가 `ini` 코드 블록으로 변환되지 않는지 확인한다.
4. 제목, 문단, 링크 및 비텍스트 블록의 보존 여부를 원본과 비교한다.
5. 외부 코드 에디터의 코드와 외부 KQL을 붙여넣어 기존 코드 블록 자동 변환이 유지되는지 확인한다.
