# DEV_260719 — 페이지 간 복사 시 전체가 코드 블록으로 변환되는 문제

## 요약

페이지의 리치 본문을 복사해 다른 페이지에 붙여넣을 때 전체가 `ini` 코드 블록으로 변환되고 일부 구조가 누락되는 문제를 `main` 브랜치에서도 확인하고 수정했다.

## 증상

- 본문 전체가 하나의 코드 블록으로 들어간다.
- 코드 블록 언어 배지에 `ini`가 표시된다.
- 제목, 문단, 굵게, 링크 등 원본 서식과 블록 경계가 사라진다.
- 이미지나 Mermaid 같은 비텍스트 노드는 평문 변환 과정에서 누락될 수 있다.

대표 원문은 아래처럼 일반 설명 문서 안에 `=`가 반복된다.

```txt
M = "마스터"
MA = "영화"
CA = "기기변경"
```

## 원인

에디터 내부 복사 시 클립보드에는 두 형식이 함께 들어간다.

- `text/html`: ProseMirror의 `data-pm-slice` 마커와 원본 리치 구조
- `text/plain`: 서식을 제거한 평문

수정 전 `handlePaste`는 `data-pm-slice`보다 `looksLikeSourceCode(text)`를 먼저 검사했다. 반복된 `=` 줄이 코드 신호로 누적되면서 일반 문서 전체를 `codeBlock` 하나로 재구성했고, 이 과정에서 리치 HTML 구조가 버려졌다. `ini` 배지는 이후 언어 자동 감지 결과였다.

이 순서는 2026-07-08의 코드/KQL 붙여넣기 수정에서 내부에 평문으로 들어간 코드를 재복사할 때 코드 블록으로 교정하기 위해 도입됐지만, 페이지 내부 복사의 원본 구조 보존과 충돌했다.

## 수정 내용

### `components/document-editor.tsx`

`data-pm-slice` 내부 복사 가드를 소스 코드 휴리스틱보다 앞으로 이동했다.

최종 처리 순서:

1. 이미지 및 내부 이미지 처리
2. 코드 에디터 전용 클립보드 감지
3. Excel/Google Sheets HTML 표 보존
4. `data-pm-slice` 내부 리치 복사 보존
5. 외부/평문 소스 코드와 KQL 휴리스틱
6. Markdown 재파서
7. 기본 ProseMirror 붙여넣기

따라서 페이지 내부 복사는 네이티브 ProseMirror 붙여넣기로 위임되어 원본 HTML 구조를 우선한다. 외부 코드 에디터, 외부 평문 코드/KQL, 외부 Markdown 붙여넣기 동작은 유지된다.

내부에 평문으로 저장된 코드/KQL을 재복사해 코드 블록으로 자동 교정하던 동작은 제거된다. 복사·붙여넣기의 데이터 충실도를 우선한 결정이다.

## 남은 수동 확인

로그인 가능한 실제 앱에서 다음을 확인한다.

1. 문제가 발생한 원본 페이지 본문을 복사한다.
2. 다른 페이지에 붙여넣는다.
3. 전체가 `ini` 코드 블록으로 변환되지 않는지 확인한다.
4. 제목, 문단, 링크 및 비텍스트 블록의 보존 여부를 원본과 비교한다.
5. 외부 코드 에디터 코드와 외부 KQL의 코드 블록 자동 변환이 유지되는지 확인한다.
