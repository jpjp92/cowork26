# DEV_260602 — main 병합 전 AGI 비활성 가드 및 검증

## 요약

`dev` 브랜치를 `main`에 병합하기 전 변경 범위를 검토했다. main 배포에서는 아직 AGI 기능을 사용하지 않을 예정이므로, 환경변수를 설정하지 않아도 AGI UI와 API가 비활성 상태로 유지되도록 서버 가드를 추가했다.

## 검토한 내용

### 브랜치 상태

- 현재 브랜치: `dev`
- 비교 기준: `main...dev`
- 워킹트리는 검토 전 깨끗한 상태였고, `main`은 `dev`의 ancestor라 fast-forward 병합 가능한 상태로 확인했다.

### 주요 변경 범위

- AGI 실행 API 및 플로팅 버튼 추가
- 페이지 전환 성능 개선
- Mermaid lazy loading
- API timing 계측
- workspace 정렬 개선
- 페이지 Markdown 다운로드 기능
- docs/history 및 docs/plans 정리

## 적용한 수정

### 1. AGI API 서버 측 feature flag 추가

`/api/agi` 라우트에 `NEXT_PUBLIC_ENABLE_AGI === 'true'` 조건을 추가했다.

AGI가 비활성화된 상태에서는 아래 메서드가 모두 `404`를 반환한다.

- `GET /api/agi`
- `POST /api/agi`
- `DELETE /api/agi`

응답:

```json
{ "error": "disabled" }
```

main/Vercel 배포에서 AGI 관련 환경변수를 넣지 않아도 API가 사실상 닫힌 상태가 된다.

관련 파일:
- `app/api/agi/route.ts`

### 2. AGI iframe postMessage target origin 제한

기존에는 페이지 컨텍스트를 AGI iframe에 보낼 때 `postMessage(..., '*')`를 사용했다. 이를 AGI URL의 origin으로 제한했다.

변경 효과:
- 선택 텍스트, 페이지 본문, 이미지 컨텍스트가 의도한 AGI origin에만 전달됨
- 잘못된 iframe 대상이나 예기치 않은 수신자로 메시지가 퍼질 가능성 완화

관련 파일:
- `components/floating-ai-button.tsx`

### 3. AGI launch 상태 처리 보정

`POST /api/agi` 요청이 실패하거나 feature flag로 비활성화되어도 `launched`가 true가 되지 않도록 변경했다.

관련 파일:
- `components/floating-ai-button.tsx`

### 4. 문서 whitespace 경고 정리

`git diff --check`에서 잡힌 trailing whitespace와 EOF 여분 빈 줄을 정리했다.

관련 파일:
- `README.md`
- `docs/plans/PLAN_20260513.md`
- `docs/plans/PLAN_20260514.md`

## Vercel 환경변수 판단

main에서 AGI를 사용하지 않을 경우 Vercel에 AGI 관련 환경변수는 설정하지 않아도 된다.

AGI 사용 시 필요한 값:

```bash
NEXT_PUBLIC_ENABLE_AGI=true
JJAPVIS_SERVER_URL=...
NEXT_PUBLIC_JJAPVIS_SERVER_URL=...
```

현재 main 배포에서는 `NEXT_PUBLIC_ENABLE_AGI`를 설정하지 않거나 `false`로 두는 것이 기본 방침이다.

## 남은 주의사항

- AGI 기능을 실제로 켤 때는 HTTPS 환경에서 HTTP iframe이 차단될 수 있으므로 AGI 서버 URL 프로토콜을 다시 확인해야 한다.
- 현재 AGI 종료 로직은 브라우저 탭 unload 시 전역 PID를 종료하는 구조라, 여러 탭에서 동시에 사용하는 시나리오는 추가 보완이 필요하다.
