# DEV_260615 — 클립보드 이미지 붙여넣기 계획

## 요약

문서 에디터에서 클립보드로 복사한 이미지를 바로 붙여넣을 수 있도록 기능 방향을 정리했다. 이미지는 `pages.content` JSON 안에 base64로 직접 저장하지 않고, Supabase Storage에 업로드한 뒤 TipTap 문서에는 이미지 URL과 메타데이터만 남기는 구조로 간다.

## 목표

- 사용자가 에디터에 이미지를 붙여넣으면 문서 안에 이미지가 삽입된다.
- 이미지 파일은 Supabase Storage bucket에 저장한다.
- `pages.content`에는 이미지 파일 자체가 아니라 얇은 참조만 저장한다.
- viewer는 이미지 조회만 가능하고, owner/editor만 이미지 업로드가 가능해야 한다.
- Markdown 다운로드 시 이미지 노드는 `![alt](url)` 형식으로 변환한다.

## 사용자가 준비할 Supabase 항목

### 1. Storage bucket

버킷 후보:

```txt
page_assets
```

권장 경로:

```txt
workspaces/{workspaceId}/pages/{pageId}/{assetId}.{ext}
```

현재 Supabase에서 `page_assets` bucket을 public bucket으로 생성했다. 초기 구현은 이 설정을 기준으로 진행한다.

- 장점: TipTap 이미지 노드에서 바로 `<img src="...">`로 렌더링 가능
- 단점: URL을 아는 사람은 이미지에 접근 가능

private bucket을 쓰려면 signed URL 발급과 만료 갱신이 필요하다. 첫 버전에서는 구현 복잡도가 커지므로 public bucket + 서버 업로드 권한 체크로 시작한다.

### 2. `page_assets` 테이블

테이블 후보:

```sql
page_assets
```

필드 후보:

```txt
id UUID primary key
workspace_id UUID not null
page_id UUID not null
storage_path TEXT not null
public_url TEXT
mime_type TEXT not null
size_bytes BIGINT not null
width INTEGER
height INTEGER
created_by UUID
created_at TIMESTAMPTZ default now()
deleted_at TIMESTAMPTZ
```

SQL Editor 실행안:

```sql
CREATE TABLE IF NOT EXISTS page_assets (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  workspace_id UUID NOT NULL REFERENCES workspaces(id) ON DELETE CASCADE,
  page_id UUID NOT NULL REFERENCES pages(id) ON DELETE CASCADE,
  storage_path TEXT NOT NULL,
  public_url TEXT,
  mime_type TEXT NOT NULL CHECK (mime_type IN (
    'image/png',
    'image/jpeg',
    'image/webp',
    'image/gif'
  )),
  size_bytes BIGINT NOT NULL CHECK (size_bytes > 0),
  width INTEGER CHECK (width IS NULL OR width > 0),
  height INTEGER CHECK (height IS NULL OR height > 0),
  created_by UUID REFERENCES auth.users(id) ON DELETE SET NULL,
  created_at TIMESTAMPTZ NOT NULL DEFAULT now(),
  deleted_at TIMESTAMPTZ,
  UNIQUE (storage_path)
);

CREATE INDEX IF NOT EXISTS page_assets_workspace_id_idx ON page_assets(workspace_id);
CREATE INDEX IF NOT EXISTS page_assets_page_id_idx ON page_assets(page_id);
CREATE INDEX IF NOT EXISTS page_assets_created_by_idx ON page_assets(created_by);
CREATE INDEX IF NOT EXISTS page_assets_active_page_idx
  ON page_assets(page_id)
  WHERE deleted_at IS NULL;

ALTER TABLE page_assets ENABLE ROW LEVEL SECURITY;

DROP POLICY IF EXISTS "page_assets_member_select" ON page_assets;
CREATE POLICY "page_assets_member_select" ON page_assets
  FOR SELECT USING (
    deleted_at IS NULL AND
    EXISTS (
      SELECT 1 FROM workspace_members
      WHERE workspace_id = page_assets.workspace_id
        AND user_id = auth.uid()
    )
  );

DROP POLICY IF EXISTS "page_assets_editor_insert" ON page_assets;
CREATE POLICY "page_assets_editor_insert" ON page_assets
  FOR INSERT WITH CHECK (
    created_by = auth.uid() AND
    EXISTS (
      SELECT 1 FROM workspace_members
      WHERE workspace_id = page_assets.workspace_id
        AND user_id = auth.uid()
        AND role IN ('owner', 'editor')
    )
  );

DROP POLICY IF EXISTS "page_assets_editor_update" ON page_assets;
CREATE POLICY "page_assets_editor_update" ON page_assets
  FOR UPDATE USING (
    EXISTS (
      SELECT 1 FROM workspace_members
      WHERE workspace_id = page_assets.workspace_id
        AND user_id = auth.uid()
        AND role IN ('owner', 'editor')
    )
  );

DROP POLICY IF EXISTS "page_assets_editor_delete" ON page_assets;
CREATE POLICY "page_assets_editor_delete" ON page_assets
  FOR DELETE USING (
    EXISTS (
      SELECT 1 FROM workspace_members
      WHERE workspace_id = page_assets.workspace_id
        AND user_id = auth.uid()
        AND role IN ('owner', 'editor')
    )
  );
```

생성 상태:

- `page_assets` Storage bucket 생성 완료
- `page_assets` 테이블 생성 완료

용도:

- 페이지별 첨부 이미지 추적

## 운영 / 보안 메모

- base64 이미지를 `pages.content`에 직접 저장하지 않는다.
- 업로드 API는 반드시 page/workspace 권한을 확인한다.
- 파일 확장자는 클라이언트 파일명보다 MIME 타입 기준으로 결정한다.
- 저장 경로에는 원본 파일명을 그대로 쓰지 않고 UUID 기반 이름을 사용한다.
- public bucket으로 시작하더라도 업로드 권한은 서버 API에서만 통제한다.
- 추후 private bucket 전환 시 signed URL 캐시와 만료 갱신 전략이 필요하다.

## 페이지 트리 드래그 계층 변경

기존 페이지 드래그는 같은 부모 아래에서 `order_index`만 바꾸는 sibling reorder로 제한되어 있었다. 상위 페이지를 다른 페이지의 하위로 넣거나, 하위 페이지를 루트/다른 부모 아래로 이동할 수 있도록 드래그 로직을 확장했다.

동작:

- 대상 행 위쪽 25%에 drop: 대상 페이지 위 sibling으로 이동
- 대상 행 아래쪽 25%에 drop: 대상 페이지 아래 sibling으로 이동
- 대상 행 가운데 50%에 drop: 대상 페이지의 하위 페이지로 이동

안전장치:

- 자기 자신에게 drop 방지
- 자기 하위 페이지 안으로 이동하는 cycle 방지
- optimistic update 후 저장 실패 시 이전 `pages` 상태로 rollback
- 하위로 넣는 경우 대상 페이지 collapse 상태를 자동 해제

저장 방식:

- 변경된 페이지들만 `PATCH /api/pages` 호출
- `parentId`와 `orderIndex`를 함께 저장
- 기존 `/api/pages` PATCH의 `parentId`, `orderIndex` 지원을 활용

관련 파일:

- `components/notion-lite-app.tsx`

## 초기 로딩 Skeleton

액션마다 skeleton을 넣으면 저장, 드래그, 붙여넣기 같은 짧은 작업에서 UI가 과하게 출렁일 수 있으므로, 첫 데이터 로딩 구간에만 skeleton을 추가했다.

적용 범위:

- 인증 후 워크스페이스 목록이 처음 로딩되는 동안 사이드바 페이지 영역에 skeleton 표시
- 선택된 워크스페이스의 페이지 목록이 처음 로딩되는 동안 페이지 트리 skeleton 표시
- 초기 문서 본문 영역에는 문서 카드 형태의 skeleton 표시
- 환경 설정 패널에서 멤버 목록이 처음 로딩되는 동안 작은 list skeleton 표시

비적용 범위:

- 저장, 이미지 업로드, 이미지 복제, 드래그 이동 같은 짧은 액션은 기존 optimistic update / 상태 배지 / 버튼 상태로 처리
- 기존 페이지 데이터가 이미 있는 상태의 background revalidate에서는 skeleton을 표시하지 않음

관련 파일:

- `components/notion-lite-app.tsx`

## 수동 테스트

클립보드 이미지 붙여넣기를 로컬 dev 환경에서 확인했다.

결과:

- 에디터에 이미지가 정상 삽입됨
- `POST /api/assets`가 `201`로 성공
- Storage 업로드 후 `page_assets` insert 성공
- 이후 `PATCH /api/pages` content 저장 성공
- 페이지 이동 후 `GET /api/pages?id=...`로 다시 불러와도 이미지 표시 유지

관찰한 timing:

```txt
POST /api/assets
request.formData=23ms page.lookup=249ms role.select=96ms file.arrayBuffer=3ms storage.upload=348ms asset.insert=122ms total=845ms

POST /api/assets
request.formData=5ms page.lookup=97ms role.select=286ms file.arrayBuffer=0ms storage.upload=650ms asset.insert=95ms total=1134ms

PATCH /api/pages
auth.getUser=145ms request.json=1ms page.lookup=92ms role.select=96ms page.update=97ms total=430ms
```

해석:

- 이미지 업로드 자체는 정상 동작한다.
- Storage 업로드가 약 350ms~650ms로 업로드 API에서 가장 큰 비중을 차지한다.
- 첫 이미지 업로드 요청은 전체 `POST /api/assets 201 in 3.1s`였지만 application-code는 약 853ms였다. 나머지는 dev 환경의 Next.js 처리/cold path 영향으로 보인다.
- content 저장은 업로드 완료 후 public URL이 들어간 image node 기준으로 수행된다.

이미지 선택 복사 테스트 절차:

```txt
1. 문서 안 이미지에 마우스를 올린다.
2. 우상단 Copy 버튼을 누른다.
3. 같은 workspace의 다른 페이지 또는 다른 workspace의 편집 가능한 페이지로 이동한다.
4. 에디터에서 붙여넣기한다.
5. POST /api/assets/clone 201 응답을 확인한다.
6. 대상 페이지 Markdown 다운로드에서 대상 page_assets URL이 들어갔는지 확인한다.
```
