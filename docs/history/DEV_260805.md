# DEV_260805 — 이미지 직접 업로드와 대용량 붙여넣기 안정화

## 요약

클립보드 이미지 업로드가 파일에 따라 성공하거나, 미리보기가 나타난 뒤 사라지는 문제를 조사했다. 초기 구조는 브라우저가 이미지 전체를 `POST /api/assets`로 보내고 Vercel Function이 Supabase Storage에 다시 업로드했다. 이 구조는 애플리케이션의 5MB 검사와 별개로 Vercel Function 요청 본문 제한의 영향을 받았다.

업로드를 Signed Upload URL 기반의 브라우저 → Supabase Storage 직접 전송으로 바꾸고, 원본 입력 한도를 20MB로 확대했다. 이후 Windows Edge에서 대용량 단일 `PUT` 연결이 `net::ERR_CONNECTION_ABORTED`로 끊기는 사례가 확인되어, 5MB 초과 정적 이미지를 브라우저에서 WebP로 최적화한 뒤 전송하도록 보완했다.

## 최종 업로드 흐름

```text
클립보드 이미지
  → 클라이언트 형식·원본 크기 검사
  → 5MB 초과 PNG/JPEG/WebP이면 WebP 최적화
  → POST /api/assets (action=prepare)
      · 로그인 및 owner/editor 권한 확인
      · 서버가 UUID 기반 Storage 경로 생성
      · Signed Upload URL 발급
  → 브라우저가 Signed URL 원문으로 Storage에 직접 PUT
  → POST /api/assets (action=complete)
      · Storage 객체 존재 확인
      · 실제 MIME·크기 재검증
      · page_assets 메타데이터 저장
  → TipTap 미리보기를 public URL 이미지로 교체
```

전송이나 완료 검증이 실패하면 `DELETE /api/assets`로 아직 등록되지 않은 Storage 객체를 정리하고, 에디터의 미리보기 노드를 제거한다. 이미 `page_assets`에 등록된 객체는 취소 API로 삭제할 수 없다.

## 파일 정책

| 항목 | 정책 |
| --- | --- |
| 원본 입력 한도 | 20MB |
| 지원 MIME | `image/png`, `image/jpeg`, `image/webp`, `image/gif` |
| PNG/JPEG/WebP 5MB 이하 | 원본 그대로 업로드 |
| PNG/JPEG/WebP 5MB 초과 | 긴 변 최대 2560px, WebP 품질 단계 조정, 최종 5MB 이하 |
| GIF | 애니메이션 보존을 위해 변환하지 않으며 최대 5MB |
| Storage bucket 제한 | 20MB 및 위 네 가지 MIME만 허용 |

최적화 결과가 5MB 이하가 되지 않거나 브라우저가 이미지를 디코딩할 수 없으면 업로드를 시작하지 않고 오류를 표시한다.

## 보안 경계

- 클라이언트가 보낸 workspace/page/path를 그대로 신뢰하지 않는다.
- API가 페이지와 워크스페이스 관계 및 owner/editor 권한을 확인한다.
- Storage 경로는 서버가 생성한 workspace/page/asset UUID 조합만 사용한다.
- Signed URL은 `upsert: false`로 발급한다.
- 완료 요청은 클라이언트가 선언한 값만 믿지 않고 Storage `info()`의 실제 크기와 MIME을 확인한다.
- DB 메타데이터 저장이 실패하면 업로드된 객체를 제거한다.
- 취소 요청은 동일 페이지의 미등록 객체에만 허용한다.
- Supabase `page_assets` 버킷에도 20MB/MIME 제한을 적용해 완료 API를 건너뛰는 우회 업로드를 제한한다.

## 연결 중단 대응

운영 Edge에서 기존 Supabase SDK `uploadToSignedUrl()` 호출이 `net::ERR_CONNECTION_ABORTED`로 종료되는 사례가 있었다. CORS preflight, Supabase 프로젝트 URL 일치, Signed Upload 자체는 정상임을 확인했다.

대응:

- 5MB 초과 정적 이미지는 전송 전에 WebP로 축소한다.
- SDK가 프로젝트 URL을 재구성하는 경로 대신 서버가 반환한 Signed URL 원문을 사용한다.
- `XMLHttpRequest`로 HTTP 상태와 Storage 오류 본문을 구분해 사용자 메시지에 반영한다.
- 브라우저가 성공 응답만 놓친 경우 완료 API가 실제 객체를 확인해 성공한 업로드를 복구한다.
- 연결 실패 메시지에는 실제 전송 파일 용량을 포함한다.

Supabase가 권장하는 TUS 재개 업로드도 검토했으나, 현재 프로젝트에서는 `createSignedUploadUrl()` 토큰을 TUS `x-signature`로 전달했을 때 `Invalid Compact JWS`가 반환됐다. 실제 프로젝트 검증에 실패한 경로는 배포하지 않았다.

## 내부 이미지 복제

`POST /api/assets/clone`은 더 이상 원본 파일을 Vercel Function 메모리로 다운로드한 뒤 재업로드하지 않는다. Supabase Storage의 서버사이드 `copy`를 사용하고, DB 메타데이터 저장 실패 시 대상 객체를 정리한다.

## 사용자 피드백

- 붙여넣기 직후 로컬 `blob:` 미리보기를 표시한다.
- 업로드/복제 중에는 자동 저장을 보류한다.
- 실패하면 미리보기를 제거하고 에디터 상단에 오류와 닫기 버튼을 표시한다.
- 지원하지 않는 형식, 20MB 초과, GIF 5MB 초과, 최적화 실패, HTTP 오류, 연결 중단, 시간 초과를 구분한다.
