# DEV_260626 — 복합 Markdown 붙여넣기 개선 진행

## 요약

Markdown 문서를 에디터에 붙여넣을 때 표만 남고 일반 텍스트와 Mermaid 블록이 사라지는 문제를 조사하고 1차 수정했다.

1차 수정 이후 사용자 캡처 기준으로 표 앞뒤 텍스트가 사라지는 문제는 해소됐다. 다만 전체 Markdown 문서 붙여넣기에서 heading, 구분선, 목록, 인용, 일부 인라인 서식이 raw Markdown 텍스트로 남는 한계가 확인됐다.

## 원래 문제

붙여넣기 handler가 아래 순서로 단일 규칙만 처리했다.

```txt
이미지
  -> 내부 이미지
  -> 마크다운 테이블
  -> 코드 블록 / Mermaid
  -> 마크다운 링크
  -> 기본 Tiptap 붙여넣기
```

`parseMarkdownTable(text)`가 전체 붙여넣기 텍스트에서 첫 번째 표만 찾아 HTML table로 변환했고, handler가 `return true`로 종료했다. 그 결과 같은 Markdown 안에 있던 일반 문단과 Mermaid code fence가 버려졌다.

## 1차 수정

`components/document-editor.tsx`에 블록 기반 Markdown paste 경로를 추가했다.

- `text/plain`을 블록 단위로 스캔
- 문단, 마크다운 표, 일반 code fence, Mermaid code fence를 원본 순서대로 보존
- Mermaid와 일반 code block은 ProseMirror node를 직접 생성
- 표와 문단은 HTML 조각을 ProseMirror parser로 변환
- 구분행 없는 파이프 텍스트는 표로 오파싱하지 않음
- fence 내부에서는 표를 탐지하지 않음

- 그러나 `#`, `##`, `---`, `- 목록`, `> 인용`, `**굵게**` 등은 일반 문서 붙여넣기에서 raw Markdown으로 남는 구간이 있음

## 다음 개선 계획

Markdown paste scanner가 아래 블록을 추가로 인식하도록 확장한다.

- Heading: `#` ~ `######`
- Horizontal rule: `---`, `***`, `___`
- Blockquote: `> 내용`
- Flat bullet list: `-`, `*`, `+`
- Flat ordered list: `1.`, `1)`
- Paragraph inline marks: bold, italic, strike, inline code, Markdown link
- Table cell inline marks: 기존 지원 유지 및 escaping 보강 유지

이번 단계의 범위는 "일반적인 문서 붙여넣기에서 raw Markdown으로 보이는 주요 문법을 렌더링"하는 것이다. 완전한 Markdown parser 도입, 중첩 리스트, task list, 복잡한 table escape 문법은 별도 범위로 둔다.

## 코드블록 fence 후속 수정

추가 캡처:

- `ref/코드블록_원본.png`
- `ref/코드블록.png`

확인된 문제:

- 원본은 ` ```` ` fence 안에 ` ```언어명 ... ``` ` 예시를 넣은 코드블록이다.
- 기존 스캐너는 정확히 ` ``` `만 fence로 인식했다.
- 그래서 바깥 ` ```` `는 일반 문단으로 남고, 안쪽 ` ``` `를 잘못 시작 fence로 잡아 뒤쪽 목록, 구분선, Mermaid 섹션까지 하나의 코드블록으로 삼켰다.

수정:

- fence 시작을 3개 이상의 backtick 또는 tilde로 인식하도록 변경
- 닫는 fence는 같은 문자이고, 여는 fence 길이 이상일 때만 닫히도록 변경
- 언어명은 `\w` 제한을 제거해 `언어명` 같은 한글 라벨도 code block language attr로 보존
- `scripts/editor-syntax-test.cjs`에 `26-nested-code-fence-example` 케이스 추가

## Markdown 다운로드 후속 검토

붙여넣기는 정상화됐지만 Markdown 다운로드 시 code fence가 살짝 틀어질 수 있는 지점을 확인했다.

원인:

- `lib/tiptap-to-markdown.ts`가 `codeBlock`과 `mermaidBlock`을 항상 3백틱 fence로 export했다.
- 코드블록 내용 안에 3백틱 예시가 있으면 다운로드된 Markdown에서 fence가 중간에 닫힐 수 있다.
- 인라인 code mark도 항상 단일 백틱으로 export해서 `` ``` `` 같은 인라인 코드 예시가 깨질 수 있다.

수정:

- code block export 시 코드 내용 안의 가장 긴 백틱 run보다 긴 fence를 자동 선택
- Mermaid block export에도 같은 fence 선택 로직 적용
- inline code export도 내용 안의 백틱 길이에 맞춰 delimiter를 자동 선택
- table cell export에서 `|`를 `\|`로 escape해 Markdown table 깨짐 방지

KQL 검토:

- KQL은 `codeBlock` 노드의 `attrs.language === "kql"`로 저장된다.
- 다운로드 시 table 변환 경로를 타지 않고 code fence로 바로 export된다.
- 따라서 `| where`, `| summarize` 같은 파이프 연산자는 escape되지 않고 코드블록 내부에 그대로 보존된다.
- KQL 코드 안에 백틱 예시가 들어가도 fence 길이를 자동으로 늘려 다운로드 Markdown이 깨지지 않도록 했다.

## 보안 검토

이번 Markdown paste/export 변경과 주변 렌더링 경로를 기준으로 XSS 및 불필요한 신뢰 경계 확장 여부를 검토했다.

확인한 점:

- Markdown paste HTML 조립 경로는 사용자 텍스트를 `escapeHtml` 처리한 뒤 제한된 태그만 생성한다.
- Markdown 링크 변환은 `http://`, `https://`만 허용하고 `rel="noopener noreferrer"`를 붙인다.
- KQL/codeBlock 다운로드 경로는 table 변환을 타지 않아 파이프 연산자가 코드블록 내부에 그대로 보존된다.

하드닝:

- Mermaid는 사용자 입력을 SVG로 렌더링한 뒤 `dangerouslySetInnerHTML`로 삽입하므로 `securityLevel: "strict"`를 명시했다.
- Mermaid config directive가 보안 설정을 바꾸지 못하도록 `secure: ["securityLevel", "startOnLoad", "maxTextSize", "secure"]`를 설정했다.
- Mermaid 입력 크기 제한을 `maxTextSize: 50000`으로 명시했다.
- 내부 이미지 복사 감지는 `img[data-cowork26-image="true"]`만 신뢰하도록 좁혔다. 기존처럼 `data-storage-path`만 있는 외부 HTML을 내부 이미지로 취급하지 않는다.
