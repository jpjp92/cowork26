# DEV_260708 — VS Code 코드 붙여넣기 시 코드블록 대신 평문으로 깨지는 문제 수정

## 요약

VS Code 등 코드 에디터에서 코드를 복사해 페이지에 붙여넣으면, 코드블록으로 들어가지 않고 줄마다 평문 문단으로 풀려버리는 문제를 조사하고 수정했다.

원인은 코드 에디터가 복사하는 `text/plain`에는 ```` ``` ```` 펜스가 없어 Markdown 재파서가 인식하지 못하고, `text/html`에도 `<pre>` 없이 줄별 `<div>`로만 담겨 네이티브 붙여넣기가 각 줄을 별도 문단으로 재구성한 데 있었다.

## 원인 분석

확인된 증상:

- VS Code에서 코드 파일을 복사해 페이지에 붙여넣으면, 코드블록이 아니라 줄마다 평문 문단으로 들어간다.

붙여넣기 경로:

- 붙여넣기는 `components/document-editor.tsx`의 `handlePaste`에서 가로챈다.
- 순서: 이미지 파일 → 내부 cowork 이미지 → `data-pm-slice` 가드 → `<table>` 가드 → `text/plain` 기반 Markdown 재파서(`parseMarkdownPasteToSlice`) → 기본 ProseMirror 붙여넣기.

근본 원인:

- 코드 에디터에서 복사한 코드의 `text/plain`은 펜스(```` ``` ````) 없는 원본 코드다. 따라서 `parseMarkdownPasteBlocks`가 코드블록을 감지하지 못하고 `handledMarkdown`이 false가 되어 `null`을 반환한다.
- Markdown 재파서가 `null`을 반환하면 `handlePaste`는 `return false`로 네이티브 ProseMirror 붙여넣기에 위임한다.
- 코드 에디터의 `text/html`은 `<pre>`가 아니라 `font-family: monospace; white-space: pre;` 스타일의 줄별 `<div>`로 구성되어, 네이티브 붙여넣기가 각 `<div>`를 별도 문단으로 만든다. → 코드블록이 아닌 평문 문단들.
- 즉 코드 붙여넣기가 코드블록이 된 적은 원래 없었다. 펜스가 있는 Markdown 텍스트를 붙여넣을 때만 코드블록이 됐다.

Excel 수정과의 관계(회귀 아님):

- Excel 표 보존 가드(`if (hasPastedTable) return false`, 커밋 `9e6e9e7`)는 `text/html`에 `<table>`이 있을 때만 동작한다.
- VS Code 코드 복사 html에는 `<table>`이 없으므로 이 가드는 코드 붙여넣기에 관여하지 않는다. 이번 이슈는 Excel 수정과 독립적이며 그 이전부터 존재했다.

## 수정

`components/document-editor.tsx`에 코드 에디터 클립보드를 감지하는 헬퍼를 추가하고, `handlePaste`에서 Markdown 재파서 이전에 코드블록으로 복원하도록 했다.

식별 시그니처:

1. `vscode-editor-data` 전용 클립보드 포맷(웹/일부 환경) — 언어 `mode`까지 포함하므로 언어 배지 복원에 사용.
2. `text/html`의 monospace + `white-space: pre` 시그니처(데스크톱→브라우저 붙여넣기 폴백).

```ts
function getCodeEditorPaste(clipboardData: DataTransfer | null | undefined) {
  if (!clipboardData) return null
  const code = clipboardData.getData('text/plain')
  if (!code || !code.includes('\n')) return null // 인라인 조각 오탐 방지: 여러 줄만 처리

  const meta = clipboardData.getData('vscode-editor-data')
  const html = clipboardData.getData('text/html') ?? ''

  if (html.includes('data-pm-slice')) return null // 내부 복사본은 별도 경로
  if (!meta && !looksLikeCodeEditorHtml(html)) return null
  // meta의 mode → lowlight 언어명으로 정규화
  ...
}
```

가드/처리:

- 이미 코드블록 안에서 붙여넣는 경우(`selection.$from.parent.type.name === 'codeBlock'`)는 네이티브 평문 삽입에 맡겨 중첩 오작동을 막는다.
- 감지되면 `codeBlock` 노드를 만들어 `replaceSelection`으로 삽입한다.

오탐 방지 설계:

- 여러 줄(`\n` 포함)일 때만 코드블록으로 처리 → 인라인 코드 조각 붙여넣기는 그대로.
- `data-pm-slice`(내부 복사), `<table>`(Excel/시트)은 배제 → 기존 표/리치 복사 동작 유지.
- `text/plain`에 펜스가 있는 순수 Markdown은 이 경로에 걸리지 않고 기존 Markdown 재파서로 처리.

## 추가 조사 — text/plain만 있는 코드 붙여넣기 (진단 로그로 확정)

JS는 코드블록으로 잘 들어갔으나(그때는 `vscode-editor-data` 메타 존재), Python은 마크다운 제목으로 오탐되고 HTML은 평문 문단으로 깨졌다. 임시 진단 로그로 실제 클립보드를 관측한 결과:

```
types = ["text/plain"]        ← text/plain 하나뿐
vscode-editor-data = (none)   ← 메타 없음
text/html = ""                ← html 없음
text/plain = "# config/usage_manager.py\r\n# 사용량 추적..."
```

- 실패하는 붙여넣기는 클립보드에 **`text/plain`만** 있고 html/메타가 전혀 없다(터미널·미리보기·에디터 외 경로, CRLF).
- 따라서 위의 메타/html 시그니처 감지는 걸릴 게 없어 통과 → 마크다운 파서가 Python `#` 주석을 제목(H1)으로 오탐.
- `text/plain`만 있을 때는 "코드"인지 "마크다운 문서"인지 구분할 확실한 신호가 없음(`# 제목` = 마크다운 헤딩 = 파이썬 주석). → 자동판별 정책 필요, **코드 휴리스틱 자동판별**로 결정.

이력 확인 결과, 펜스(```) 없는 raw 코드는 과거 어떤 버전에서도 코드블록으로 자동 변환된 적이 없었다(원조 `parseMarkdownCodeBlock`도 펜스 정규식 기반). "예전엔 잘 됐다"는 기억은 펜스 코드이거나 VS Code 에디터 복사(메타 존재) 케이스로 추정.

## 추가 수정 — 소스 코드 휴리스틱 자동판별

붙여넣기 내용이 소스 코드로 보이면 코드블록으로 감싼다. (처음엔 `!pasteHtml` 게이트로 text/plain 전용이었으나, 아래 KQL 수정에서 게이트를 제거해 html 동반 붙여넣기도 판정하도록 확장했다.)

- `looksLikeSourceCode(text)`: 코드 신호 줄 비율로 판정. 키워드(`import/def/const/function/class/return/...`), 구문기호(`;`, `{`, `}`, `=>`, 할당 `=`), 태그(`<...>`, `<!DOCTYPE`), 전처리기(`#include`), 2칸 이상 들여쓰기 등을 신호로 봄. `codeLines >= 2 && ratio >= 0.3`이면 코드로 간주.
- 마크다운 오탐 방지: 펜스(```)나 마크다운 표 구분행이 있으면 즉시 false → 기존 마크다운 파서가 처리.
- 코드블록 내부에서 붙여넣기(`inCodeBlock`) 시엔 적용하지 않음.
- 언어 배지: `detectCodeLanguage(text)`로 언어를 추정해 `language` 속성에 넣는다(배지 데코레이션이 `node.attrs.language`가 있을 때만 붙기 때문). 명시적 시그니처(html/json/python/typescript/javascript/css/bash) 우선, 없으면 `lowlight.highlightAuto`(relevance≥5) 폴백, 그래도 애매하면 null(하이라이팅은 auto라 유지).

순수 함수 단위 검증:

- 코드(Python `#` 주석 포함 / HTML `<!DOCTYPE>` / JS require / dict 형태) → 모두 코드블록 ✅
- 마크다운 문서(case25) / 마크다운 표(case17) / 펜스 KQL(case15) / 산문 / 파이프 텍스트(case23) / 불릿 리스트 → 모두 기존 경로 유지 ✅

## 추가 수정 — Azure KQL 및 html 동반 코드 붙여넣기

Python/JS/TS/JSON/YAML/HTML은 코드블록으로 잘 들어갔으나 KQL만 평문으로 남는 문제가 있었다. 원인 두 가지:

1. KQL을 Azure 포털(웹)에서 복사하면 `text/html`이 동반되어 `!pasteHtml` 게이트에 막혔다.
2. `| where`, `| project` 같은 파이프 리딩 KQL 구문은 일반 코드 신호(`import`/`;`/`{}` 등)에 거의 안 걸린다(특히 짧은 쿼리는 신호 0).

수정:

- `KQL_OPERATOR_LINE` 패턴(`| where/project/extend/summarize/order by/join/...`) 추가. `looksLikeSourceCode`에서 이 라인이 2개 이상이면 코드로 확정.
- `detectCodeLanguage`에서 동일 조건이면 `kql` 배지 부여(lowlight에 grammar는 없어 하이라이팅은 생략, 코드블록/배지는 정상).
- `handlePaste`의 `!pasteHtml` 게이트 제거 → 코드처럼 보이면 html 유무와 무관하게 코드블록. 내부 복사(`data-pm-slice`)·표(`<table>`)는 앞 단계에서 이미 위임되므로 안전.

검증(순수 함수):

- 긴 KQL / 짧은 KQL(빈 줄 포함) → 코드블록 + `kql` 배지 ✅
- 마크다운 표 / 펜스 `` ```kql `` / 산문 → 기존 경로 유지 ✅

## 추가 수정 — 내부 복사(pm-slice)한 코드/KQL이 코드 감지를 못 타던 문제

KQL이 여전히 평문으로 들어가 진단 로그로 클립보드를 재관측한 결과:

```
looksLikeSourceCode = true
detectCodeLanguage  = kql
hasPastedTable      = false
html[0:200] = "<html>...<p data-pm-slice=\"1 1 []\">union AppDependencies..."
```

- 코드 감지는 정상(`true`, `kql`)이지만, html에 `data-pm-slice`가 있어 **코드 감지보다 먼저** 있던 pm-slice 가드(`return false`)에 걸려 네이티브 위임 → 평문.
- 즉 KQL을 에디터 안에 문단으로 붙여둔 것을 **다시 복사(내부 복사본이라 pm-slice 마커 부착)**해 붙여넣는 경로였다.

수정 — `handlePaste` 가드 순서 재배치: **표 가드 → 코드 감지 → pm-slice 가드**.

- 내부 복사한 코드/KQL 문단 → 코드 감지가 먼저 잡아 코드블록.
- 내부 복사한 표 → 표 가드에서 보존. 코드처럼 보이지 않는 리치 서식(제목/목록/볼드) → `looksLikeSourceCode=false`라 통과 후 pm-slice 가드에서 네이티브 보존(DEV_260629 동작 유지).

## 최종 handlePaste 처리 순서

`components/document-editor.tsx` 기준:

1. 이미지 파일 / 내부 cowork 이미지
2. 코드 에디터 클립보드 감지(`getCodeEditorPaste`: `vscode-editor-data` 또는 monospace html) → 언어 배지 포함 코드블록
3. `<table>` 가드 → 네이티브 위임(Excel/시트 표 보존)
4. 소스 코드/KQL 휴리스틱(`looksLikeSourceCode` + `detectCodeLanguage`) → 코드블록
5. `data-pm-slice` 가드 → 네이티브 위임(내부 리치 복사 서식 보존)
6. Markdown 재파서(`parseMarkdownPasteToSlice`) → 헤딩/목록/표/펜스코드/인용 등
7. 기본 ProseMirror 붙여넣기

## 관련 함수 (components/document-editor.tsx)

- `getCodeEditorPaste` / `looksLikeCodeEditorHtml` / `normalizeCodeLanguage` — VS Code 등 에디터 복사 감지
- `looksLikeSourceCode` / `CODE_LINE_SIGNAL` / `KQL_OPERATOR_LINE` — plain text 코드/KQL 휴리스틱
- `detectCodeLanguage` — 명시적 시그니처 + `lowlight.highlightAuto` 폴백으로 언어 배지 추정
