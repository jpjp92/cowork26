# DEV_260623 — KQL 붙여넣기 테이블 오파싱 수정

## 요약

KQL 쿼리를 에디터에 붙여넣을 때 테이블로 잘못 파싱되는 버그를 수정했다.

## 원인

`parseMarkdownTable` 함수에 두 가지 문제가 있었다.

### 문제 1 — 코드펜스 내 콘텐츠를 테이블로 파싱

KQL 코드 블록(` ```kql\n...\n``` `)을 에디터에서 복사하면 클립보드에 마크다운 코드펜스 형태로 저장된다. 붙여넣기 시 paste 핸들러는 `parseMarkdownTable` → `parseMarkdownCodeBlock` 순으로 검사한다.

`parseMarkdownTable`은 ` ``` ` 줄을 `.filter(line => !line.startsWith('```'))`로 제거한 뒤 남은 KQL 내용의 `|` 문자를 테이블로 오인했다.

### 문제 2 — 구분행 없는 파이프 라인을 테이블로 파싱

KQL은 각 파이프라인 단계를 `| where`, `| extend`, `| summarize` 등 줄 앞에 `|`를 붙여 표기한다. `parseMarkdownTable`의 `else` 브랜치는 마크다운 구분행(`| --- | --- |`)이 없어도 `|`를 포함한 연속 줄을 테이블로 처리했다. 이 때문에 코드펜스 없이 순수 KQL 텍스트를 붙여넣어도 테이블로 렌더링됐다.

## 수정

### `components/document-editor.tsx`

**수정 1** — 코드펜스로 시작하는 텍스트는 즉시 `null` 반환:

```ts
function parseMarkdownTable(text: string) {
  if (text.trimStart().startsWith('```')) return null
  // ...
}
```

**수정 2** — 구분행(`---`) 없는 파이프 테이블 파싱 경로 제거:

마크다운 테이블은 항상 헤더 행 다음에 `| --- | --- |` 구분행이 있어야 한다. 구분행이 없으면 `null`을 반환하도록 `else` 브랜치를 삭제했다.

```ts
// 변경 전
if (dividerIndex !== -1) {
  // 구분행 있는 경우
} else {
  // 구분행 없이도 파이프 라인을 테이블로 처리 (제거)
}

// 변경 후
if (dividerIndex === -1) return null
// 구분행 있는 경우만 테이블로 처리
```

## 영향 범위

- KQL을 포함한 파이프 연산자(`|`)가 줄 앞에 오는 모든 언어(Bash 파이프 등)에서 동일 버그가 방지된다.
- 정상적인 마크다운 테이블(구분행 포함)은 기존과 동일하게 동작한다.
