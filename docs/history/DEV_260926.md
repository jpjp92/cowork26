# DEV_260926 — 모바일 탐색과 노션형 페이지·표 인터랙션

## 요약

모바일에서 사이드바가 세로 화면 첫 진입 시 보이지 않고 화면 회전 뒤에야 나타나는 문제를 보완했다. 페이지 트리에는 우클릭과 `⋯` 버튼이 공유하는 작업 메뉴를 추가했고, 문서 편집기에는 `/table`·`/표` 기반 표 생성과 선택한 표에 대한 문맥 작업 메뉴를 추가했다.

표 관련 UI는 편집 중 계속 커서를 따라다니지 않도록 생성 메뉴는 명령 문단, 편집 메뉴는 표 전체에 고정했다. 넓은 표는 문서와 사이드바 폭을 밀어내지 않고 표 wrapper 내부에서만 가로 스크롤된다.

## 모바일 사이드바 안정화

- 헤더 브랜드는 별도 `C` 박스 없이 `Cowork26` 워드마크만 표시하고, 계정 이메일은 설정 내부에서만 보여준다.
- Next.js viewport에 `device-width`, 초기 배율, `viewport-fit=cover`를 명시했다.
- 모바일 backdrop과 sidebar 표시를 `visibility`·transform 조합 대신 실제 `hidden`/`block`·`flex` 전환으로 단순화했다.
- 데스크톱 `md` 이상에서는 기존 고정 sidebar 동작을 유지한다.
- 검색은 데스크톱과 모바일 모두 sidebar의 Pages 영역에 유지해 기능 위치를 통일했다. 모바일에서는 페이지 탐색 drawer를 연 뒤 44×44px 검색 버튼으로 실행한다.
- 모바일 설정은 `md` 미만에서 설정 버튼 방향과 이어지는 전체 높이 우측 drawer로 표시하고 backdrop, 내부 세로 스크롤과 safe-area 여백을 적용했다. 640–767px 화면에서 데스크톱 dropdown으로 조기 전환되던 breakpoint 불일치도 제거했다.

## 페이지 트리 공통 메뉴

- 페이지 행 우클릭과 `⋯` 버튼이 하나의 context menu를 사용한다.
- 데스크톱에서는 trigger 좌표 주변에 표시하고 viewport 경계에서 위치를 보정한다.
- 모바일에서는 같은 작업을 하단 sheet로 표시한다.
- 현재 제공 작업은 페이지 열기, 하위 페이지 추가, Markdown 다운로드, 삭제다.
- 편집 권한이 없는 사용자는 변경 작업을 볼 수 없다.
- 바깥 클릭, Escape, scroll, resize에서 메뉴를 닫는다.

이름 변경, 복제, 명시적 이동과 방향키 roving focus 및 trigger 포커스 복귀는 후속 작업이다.

## 표 생성 UX

- 빈 문단에서 `/table` 또는 `/표`를 입력하면 작은 `표 만들기` 버튼이 나타난다.
- 버튼을 펼쳐 2×2, 3×3, 4×4 크기를 선택하면 header row가 포함된 표를 생성한다.
- 상단 고정 툴바는 두지 않아 일반 문서 편집 화면의 밀도를 유지한다.
- 메뉴는 현재 명령 문단을 기준으로 고정해 입력 위치를 옮기지 않는 한 커서를 따라다니지 않는다.

전체 slash menu, 블록 `+` 진입점과 1×1~8×8 grid 선택기는 후속 범위다.

## 표 편집 UX

- 표 내부에 selection이 있을 때 표 전체를 기준으로 작은 `표 옵션` 버튼을 표시한다.
- 버튼을 펼치면 가로로 긴 툴바 대신 세로형 메뉴가 나타나며, 길어지면 메뉴 내부에서 스크롤된다.
- 제공 작업은 다음과 같다.
  - 행 뒤 추가 및 현재 행 삭제
  - 열 뒤 추가 및 현재 열 삭제
  - header row 전환
  - 선택 가능한 셀 병합 또는 병합 셀 분할
  - 표 전체 삭제
- 실행할 수 없는 병합·분할 작업은 editor command 상태에 따라 비활성화한다.
- 작업 실행 뒤 메뉴를 접어 편집 화면을 계속 가리지 않게 한다.

모바일에서 여러 셀을 선택해 병합하는 흐름과 행·열 앞쪽 추가, 폭 초기화는 후속 보완 대상이다.

## 표와 문서 폭

- 편집기와 ProseMirror에 `min-width: 0`, `max-width: 100%` 경계를 적용했다.
- table wrapper는 문서 폭을 넘지 않으며 넓은 표만 wrapper 내부에서 가로 스크롤된다.
- 문서 바깥이나 sidebar 영역까지 표가 침범하지 않게 했다.

## 선택 텍스트 글자 크기

- 일반 본문과 표 셀에서 텍스트를 선택하면 공통 `글자 크기` BubbleMenu가 나타난다.
- 메뉴는 평소 `크기: 현재값` 버튼만 표시하고 펼쳤을 때 `작게(13px) / 기본 / 크게(20px)`를 제공한다.
- `기본`은 임의 크기를 덮어쓰지 않고 `fontSize` mark를 제거해 문서 기본 크기를 상속한다.
- 선택을 유지한 채 mark를 적용하며 현재 크기는 `aria-pressed`와 배경색으로 표시한다.
- 코드 블록과 비어 있는 선택에서는 메뉴를 표시하지 않는다.

굵게, 기울임, 링크와 문단 타입 등 전체 텍스트 서식 메뉴는 후속 범위다.

## 입력 글자 수 제한 검토

글자 수와 요청 크기 제한은 `docs/plans/PLAN_20260926_INPUT_LIMITS.md`에 계획만 정리했다. 현재 코드에는 아직 적용하지 않았다.

권장안은 페이지 제목 200자, 워크스페이스 이름과 표시 이름 80자, 이메일 254자, 검색어와 이미지 alt 200자, 문서 JSON 2MiB, 일반 JSON 요청 2.5MiB다. 이미지 파일의 기존 20MiB 정책은 유지한다.

- `npm run test:editor-paste-priority` 통과
- `npm run test:image-assets` 통과
- `npm run test:page-parent-validation` 통과

- `git diff --check` 통과

## 남은 개선 항목

- `sm`과 `md`가 섞인 문서·오버레이 breakpoint를 앱 기준인 `md`로 통일
- 워크스페이스 이름 변경 등 관리 기능을 sidebar에서 설정 drawer로 정리
- 설정 drawer의 focus trap, 최초 포커스와 trigger 포커스 복귀
- 멤버 제거 및 기존 멤버 역할 변경을 명시적인 UI로 제공
- 영어·한국어 문구와 문자·SVG 아이콘 체계 통일
- 일반 요소의 강한 border·shadow를 줄이고 주요 CTA에만 시각적 강조 집중
- 페이지 이름 변경, 복제, 이동 작업을 공통 메뉴에 연결
- 메뉴 방향키 탐색과 trigger 포커스 복귀
- 전체 slash menu, 텍스트 선택 BubbleMenu, 블록 handle과 drag
- 모바일 다중 셀 선택 및 병합 UX
- 입력 글자 수·JSON 요청 크기 제한 구현과 DB constraint 적용
- 실제 모바일 브라우저에서 sidebar 첫 진입·회전·키보드 상태 확인
- 기존 로그에서 확인된 `mathInline` invalid node 경고 별도 조사
