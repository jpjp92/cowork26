# DEV_260629 — 페이지 간 복사 시 서식 유실 수정

## 요약

리치 표/제목이 있는 페이지를 다른 페이지에 복사·붙여넣을 때 표가 셀 단위로 풀리고 모든 서식이 평문으로 바뀌는 문제를 조사하고 수정했다.

원인은 에디터 내부 복사에서도 `text/plain` 기반 Markdown 재파서가 동작하면서, 제목 "1. ..."이 순서 목록으로 오탐되어 리치 `text/html`을 통째로 버리고 붙여넣기 전체를 평문으로 재구성한 데 있었다.

## 원인 분석

확인된 증상:

- 리치 표/제목이 있는 페이지를 다른 페이지에 붙여넣으면 표가 셀 단위로 풀리고 모든 서식이 평문으로 바뀐다.

붙여넣기 경로:

- 붙여넣기는 `components/document-editor.tsx`의 `handlePaste`에서 가로챈다.
- 순서: 이미지 파일 → 내부 cowork 이미지 → `text/plain` 기반 Markdown 재파서(`parseMarkdownPasteToSlice`) → 기본 ProseMirror 붙여넣기.

근본 원인:

- 에디터 내부(페이지 → 페이지) 복사 시 클립보드에는 서식이 보존된 `text/html`과 평문 `text/plain`이 함께 담긴다.
- `handlePaste`가 `text/html`을 무시하고 `text/plain`만 보고 Markdown 재파서를 돌렸다.
- 리치 문서를 복사하면 `text/plain`에서는 `#`, `|`, `>` 같은 마크다운 기호가 사라지지만, 제목 "1. 의도 분류"처럼 `1.`로 시작하는 평문이 순서 목록 패턴(`ORDERED_LIST_PATTERN = /^\d+[.)]\s+(.+)$/`)에 오탐된다.
- `handledMarkdown`은 all-or-nothing 전역 플래그라서, 단 한 줄만 마크다운처럼 보여도 붙여넣기 전체를 lossy한 `text/plain` 기준으로 재구성하고 리치 `text/html`을 통째로 버린다.
- 그 결과 `text/plain`에 `|`가 없는 표는 셀마다 별도 문단으로 풀리고, 제목/볼드/인용도 평문화됐다.

오탐 재현 확인:

```txt
"1. 의도 분류 (Intent Classification)"  -> ORDERED-LIST 매칭
```

## 수정

`components/document-editor.tsx`의 `handlePaste`에서 Markdown 재파서 호출 직전에 가드를 추가했다.

```ts
const pasteHtml = event.clipboardData?.getData('text/html') ?? ''
if (pasteHtml.includes('data-pm-slice')) return false
```

- ProseMirror가 내부 복사 시 래퍼에 붙이는 `data-pm-slice` 마커가 `text/html`에 있으면, Markdown 재파서를 건너뛰고 `return false`로 네이티브 리치 붙여넣기에 위임한다.
- 따라서 페이지 간 리치 복사는 표/제목/볼드 등 서식이 그대로 보존된다.
- 외부에서 복사한 순수 Markdown 평문에는 `data-pm-slice`가 없으므로 기존 변환 동작이 그대로 유지된다.
